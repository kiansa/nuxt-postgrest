The module has no options of its own: it's configured with `runtimeConfig`, which you can set in `nuxt.config.ts` and override per environment with variables. You normally only need the URL.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-postgrest'],
  runtimeConfig: {
    public: { 
      postgrestUrl: '', // automatically read from NUXT_PUBLIC_POSTGREST_URL
      postgrestKey: '' // automatically read from NUXT_PUBLIC_POSTGREST_KEY
    },
    postgrestSecretKey: '', // automatically read from NUXT_POSTGREST_SECRET_KEY
    postgrestJwtSecret: '', // automatically read from NUXT_POSTGREST_JWT_SECRET
  },
})
```

## Runtime config

| Key | Environment variable | Default | Description |
| --- | --- | --- | --- |
| `public.postgrestUrl` | `NUXT_PUBLIC_POSTGREST_URL` | `''` | PostgREST API URL. Required. |
| `public.postgrestKey` | `NUXT_PUBLIC_POSTGREST_KEY` | `''` | Public anon JWT sent when no user token is available. Empty means no `Authorization` header, so PostgREST uses its `db-anon-role`. |
| `postgrestJwtSecret` | `NUXT_POSTGREST_JWT_SECRET` | `''` | Server only. Secret `mintJwt()` signs tokens with. Must equal PostgREST's `jwt-secret`. |
| `postgrestSecretKey` | `NUXT_POSTGREST_SECRET_KEY` | `''` | Server only. Secret JWT for `usePostgrestAdmin()`. |

Environment variables override `nuxt.config.ts` at runtime, without rebuilding.

There's no schema option: clients default to Postgres's `public` schema, and [`createPostgrestClient`](/guide/composables#createpostgrestclientoptions) takes an explicit `schema` for anything else (multi-tenant clients, non-default schemas).

::warning
`NUXT_POSTGREST_SECRET_KEY` usually maps to a role that bypasses RLS. It is never exposed to the client, but keep it out of `nuxt.config.ts` and version control.
::
