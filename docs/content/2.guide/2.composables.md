All composables are auto-imported and return a typed `PostgrestClient`.

## `usePostgrest(options?)`

For components, pages and plugins. Works on the client and during SSR.

```ts
const client = usePostgrest()
const { data, error } = await client.from('todos').select('id, title')
```

The token is resolved in this order:

1. `options.token`, if you pass one
2. The token cookie that [`setPostgrestToken()`](/guide/authentication) wrote
3. The public anon `key`
4. No `Authorization` header (PostgREST's `db-anon-role`)

| Option | Type | Description |
| --- | --- | --- |
| `token` | `string` | Explicit JWT. Wins over everything else. |
| `headers` | `Record<string, string>` | Extra headers for every request. |

Wrap queries in `useAsyncData` so SSR results are transferred to the client instead of refetched:

```ts
const client = usePostgrest()

const { data } = await useAsyncData('todos', async () => {
  const { data, error } = await client.from('todos').select('*')
  if (error) throw error
  return data
})
```

## `usePostgrestUser(event, options?)`

For Nitro server routes. Acts as the requesting user, so RLS applies. Token resolution matches `usePostgrest()`: your `token` option, then the token cookie, then the anon key.

```ts [server/api/my-todos.get.ts]
export default defineEventHandler(async (event) => {
  const client = usePostgrestUser(event)
  const { data, error } = await client.from('todos').select('*')
  if (error) throw createError({ statusCode: 500, message: error.message })
  return data
})
```

Options are the same as `usePostgrest()`.

## `usePostgrestAdmin()`

For Nitro server routes that need privileged access: background jobs, webhooks, admin tools. Uses `NUXT_POSTGREST_SECRET_KEY` and is created once per server process.

```ts [server/api/admin/todos.get.ts]
export default defineEventHandler(async () => {
  const db = usePostgrestAdmin()
  const { data } = await db.from('todos').select('*')
  return data
})
```

::warning
Anything the admin role can see, this client can see. Authorize the request yourself before using it.
::

### Share it as a server util

If most of your server routes need the admin client, export it once from a server util. Nitro auto-imports it everywhere in `server/`:

```ts [server/utils/db.ts]
export const db = usePostgrestAdmin()
```

```ts [server/api/admin/todos.get.ts]
export default defineEventHandler(async () => {
  const { data } = await db.from('todos').select('*')
  return data
})
```

For another schema, switch on the same client with `db.schema('auth')`, or export a dedicated client built with [`createPostgrestClient`](#createpostgrestclientoptions):

```ts [server/utils/db.ts]
import type { Database } from '#shared/types/database.types'

export const db = usePostgrestAdmin()

const config = useRuntimeConfig()

export const dbAuth = createPostgrestClient<Database, 'auth'>({
  url: config.public.postgrestUrl,
  key: config.postgrestSecretKey,
  schema: 'auth',
})
```

`schema` sets the `Accept-Profile` and `Content-Profile` headers for you. The `'auth'` generic needs that schema in your generated types, see [Types](/guide/types).

::note
A module-level `export const db = usePostgrestAdmin()` runs when the server starts, so a missing `NUXT_PUBLIC_POSTGREST_URL` or `NUXT_POSTGREST_SECRET_KEY` fails the boot instead of the first admin request.
::

## `createPostgrestClient(options)`

Build a client with explicit connection details. Available in app and server code. Use it for multi-tenant setups, other PostgREST instances or other schemas.

```ts
const tenant = createPostgrestClient({
  url: `https://${tenantId}.api.example.com`,
  key: tenantJwt,
})
```

| Option | Type | Description |
| --- | --- | --- |
| `url` | `string` | PostgREST URL. Required. |
| `key` | `string` | JWT sent as `Authorization: Bearer`. Omit for anon. |
| `schema` | `string` | Postgres schema to target. |
| `headers` | `Record<string, string>` | Extra headers. Can override `Authorization`. |
| `fetch` | `typeof fetch` | Custom fetch implementation. |
| `timeout` | `number` | Request timeout in milliseconds. |

It's typed with your `Database` by default. Pass generics to change the database or schema:

```ts
const internal = createPostgrestClient<Database, 'internal'>({ url, key, schema: 'internal' })
```
