You don't need a platform to ship a real product. One small VPS can run your Nuxt app, PostgREST and Postgres, with automatic HTTPS, and your database access rules live in Postgres where they belong.

This is an opinionated sketch, not the only way. It assumes you've already run the stack once with the [local setup](/playbooks/local-postgrest).

## The shape

```text
browser → Caddy (HTTPS) → Nuxt (Nitro) → PostgREST → Postgres
└──────────────── one small VPS, Docker Compose ───────────────┘
```

- **Caddy** terminates TLS and gets certificates for you.
- **Nuxt** is your app, built with the default Node server preset.
- **PostgREST** and **Postgres** are the same containers you ran locally.
- Only Caddy publishes ports. Postgres is never reachable from the internet.

## Keep PostgREST private (recommended)

If every query goes through your Nuxt server routes, PostgREST doesn't need a public address at all. Point the module at the internal Docker hostname and store the user's token under `secure`, so the browser never sees it or talks to PostgREST:

```bash [.env]
NUXT_PUBLIC_POSTGREST_URL=http://postgrest:3000
```

Query with [`usePostgrestUser(event)`](/guide/composables#usepostgrestuserevent-options) in `server/api/*` and keep the token in `session.secure`, as described in [Authentication](/guide/authentication).

::note
Components that call `usePostgrest()` run in the browser after hydration, so they need a PostgREST URL the browser can reach. If you use it client-side, expose PostgREST on its own subdomain instead (see below).
::

## Compose file

```yaml [docker-compose.yml]
services:
  db:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    # no `ports:` — Postgres stays on the internal network

  postgrest:
    image: postgrest/postgrest:v16.3
    restart: unless-stopped
    depends_on: [db]
    environment:
      PGRST_DB_URI: postgres://authenticator:${AUTHENTICATOR_PASSWORD}@db:5432/postgres
      PGRST_DB_SCHEMAS: public
      PGRST_DB_ANON_ROLE: anon
      PGRST_JWT_SECRET: ${PGRST_JWT_SECRET}
      PGRST_DB_MAX_ROWS: 1000

  app:
    build: .
    restart: unless-stopped
    depends_on: [postgrest]
    environment:
      NUXT_PUBLIC_POSTGREST_URL: http://postgrest:3000
      NUXT_POSTGREST_SECRET_KEY: ${POSTGREST_SECRET_KEY}
      NUXT_SESSION_PASSWORD: ${NUXT_SESSION_PASSWORD}

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports: ['80:80', '443:443']
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
    depends_on: [app]

volumes:
  pgdata:
  caddy_data:
```

```text [Caddyfile]
example.com {
  reverse_proxy app:3000
}
```

Reuse the `init.sql` from the [local guide](/playbooks/local-postgrest), but use real passwords for `authenticator`, and enable row-level security on every table you create.

::warning
Postgres 18 images keep data under `/var/lib/postgresql`. If you pin an older major version, check that image's documented data directory before mounting a volume.
::

## Secrets

Generate each secret once and keep them out of git:

```bash [Terminal]
openssl rand -base64 48   # PGRST_JWT_SECRET, NUXT_SESSION_PASSWORD, database passwords
```

`NUXT_POSTGREST_SECRET_KEY` is a JWT for the privileged role, signed with the same `PGRST_JWT_SECRET`. Mint it once:

```ts [scripts/mint-service-key.mjs]
import { SignJWT } from 'jose'

const secret = new TextEncoder().encode(process.env.PGRST_JWT_SECRET)
console.log(
  await new SignJWT({ role: 'service_role' })
    .setProtectedHeader({ alg: 'HS256' })
    .setIssuedAt()
    .setExpirationTime('10y')
    .sign(secret),
)
```

::warning
That role bypasses RLS. It belongs only in the server environment, never in a `NUXT_PUBLIC_*` variable.
::

## Exposing PostgREST (optional)

If you do call PostgREST from the browser, give it its own hostname in the Caddyfile and point `NUXT_PUBLIC_POSTGREST_URL` at it:

```text [Caddyfile]
api.example.com {
  reverse_proxy postgrest:3000
}
```

Then RLS is the only thing between the internet and your data, so double-check every policy and keep `PGRST_DB_ANON_ROLE` as restricted as you can.

## Backups

The cheapest backup that works is a nightly dump copied off the machine:

```bash [backup.sh]
docker compose exec -T db pg_dump -U postgres postgres | gzip > "backup-$(date +%F).sql.gz"
```

Run it from cron, copy the file to object storage or another machine, and test a restore before you need one.

## Deploying updates

```bash [Terminal]
git pull
docker compose up -d --build
```

Compose recreates only what changed. Schema changes go in as SQL migrations you run against the database before deploying the code that needs them.
